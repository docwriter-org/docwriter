---
title: "Your first writing workflow"
---

Use this walkthrough for a complete writing project. You will give the agent examples before you write, improve a draft while teaching it your preferences, and ask several reviewer agents to critique the finished draft.

## Connect a provider

Before you start, follow the steps in [Connect a provider](/connect-provider). Continue after your provider and model appear in the header and the test request succeeds.

## Add writing references

Give the agent examples of your writing before you ask it to help with the draft. Click the references pill in the header, or open **Settings**, then **Writing references**. Paste three passages, run the analysis, pick between close passages when asked, and finalize the skill.

The full screenshot walkthrough is in [Writing references](/customize/references).

<Frame caption="Writing references are available under Settings.">
  ![The Writing references panel with options for adding source material](/images/writing-references-panel.png)
</Frame>

## Set the intended audience

Open **Settings**, then **Intended audience**. Describe who you are writing for in your own words, then choose **Save**.

For example:

```text
Busy engineering managers who already know Kubernetes; skip basics, keep examples concrete and short.
```

You can change or clear the audience later when the reader changes.

## Start writing

Open an existing Markdown file or choose **New file** in the file tree. Write the opening in your own words so the agent has your point and phrasing to work from. You can find the latest draft in the project file because DocWriter saves your work as you type.

<Frame>
  ![A new draft open in the DocWriter source editor](/images/quickstart-essay-open.png)
</Frame>

## Ask for an edit while you write

Select the opening paragraph and type:

```text
Rewrite this opening in fewer words. Keep my point and match "Published posts in my voice."
```

Choose **Direct edit** when you want proposed wording, or **Plan first** when you want to review the approach before the agent changes anything. You can continue writing elsewhere while the agent works.

<Frame caption="Select a passage to give the agent feedback beside the text.">
  ![The feedback popup attached to selected text](/images/inline-feedback-popup.png)
</Frame>

## Review the proposed change

You will see the proposed wording in the editor and a review card in the comment gutter beside it. You can use **Accept** when the proposal says what you mean. You can use **Reject** when you want to keep the current text.

<Frame>
  ![A proposed edit in the comment gutter beside the changed text](/images/quickstart-pending-edit.png)
</Frame>

If you change the same passage before reviewing a suggestion, the suggestion may become stale. Reject it and ask the agent for a new edit based on the current text.

## Turn feedback into rules

Save a writing rule when the same preference should apply to later requests. For example, if you repeatedly ask the agent to use complete sentences, add that instruction once as a rule.

Open the rules toolbar above the editor and choose **Add rule**. The agent can also suggest a rule after it notices a repeated preference. Accept a proposed rule when you want to keep using it, or dismiss it when the feedback applies only to the current passage.

<Frame caption="Writing rules appear in the toolbar above the editor.">
  ![The writing rules panel with saved instructions](/images/writing-rules-panel.png)
</Frame>

Continue drafting, reviewing suggestions, and adding rules when a preference repeats. The agent can use both the references and enabled rules on later requests.

## Run final critique passes

When the draft is complete, open **Settings**, then **Critique pass**. Choose a reviewer based on the feedback you need. The Copy Editor checks sentences, the Skeptic checks unsupported claims, the PhD Advisor checks the argument, and Fresh Eyes checks what may confuse a new reader.

<Frame caption="Choose a reviewer from Settings, then Critique pass.">
  ![The built in reviewer agents in the Critique pass menu](/images/critique-pass-menu.png)
</Frame>

Each critique pass uses one reviewer at a time. You can run several reviewers in sequence to get feedback from different points of view. When you run a pass, the reviewer reads the active draft. You receive focused findings as comments, with a proposed edit when the reviewer has a concrete fix.

<Frame>
  ![A reviewer comment attached to the passage it discusses](/images/comment-thread.png)
</Frame>

Reply when a finding needs discussion. Accept a linked edit when the wording improves the draft, or resolve the thread when no change is needed.

## Finish the project

Open the project file in another editor to confirm that the accepted text is plain Markdown. Your comments and pending suggestions stay in DocWriter until you resolve the comments and accept or reject the suggestions.

Read [Writing references](/customize/references), [Intended audience](/agent/customize#set-the-intended-audience), [Writing rules](/customize/rules), and [Comments and critique](/agent/comments-and-critique) for the full controls. Read [Recovery](/help/recovery) if the editor, provider, or proposal does not behave as described.
