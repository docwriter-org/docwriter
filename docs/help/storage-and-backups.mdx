---
title: "Storage and backups"
description: "Back up the document text and the DocWriter state you want to keep."
---

Your workspace files contain the document text. The `.docwriter` folder contains comments, pending reviews, sessions, rules, and other DocWriter state.

## Choose what to back up

Back up the writing project files when you only need the current text. Git is suitable for these plain files.

Also back up `.docwriter/docwriter.db` when you need comments, pending reviews, tab state, rules, reviewers, sessions, and interface settings.

Back up `.docwriter/hooks.json` when the workspace uses hooks. Keep any project skills stored outside the database with the rest of the project.

Do not commit API keys. Decide whether conversation and comment history belongs in the repository before adding `.docwriter`.

## Create a consistent backup

Stop DocWriter before copying the database. Then copy:

- The writing project files.
- `.docwriter/docwriter.db`.
- `.docwriter/hooks.json`, when it exists.
- Project skills and other saved files outside the database.

Temporary agent files under `.docwriter/agent/scratch/` usually do not need a backup.

## Restore a backup

Restore the project files and matching `.docwriter` folder before starting DocWriter. Restoring only the plain files keeps the text but creates new DocWriter state as each file opens.

Read [How DocWriter saves your work](/reference/how-it-works) for the relationship between the live document, database, and workspace file.
