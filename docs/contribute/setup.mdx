Use this page when you want to change DocWriter itself. If you only want to write in DocWriter, follow the [installation guide](/install) instead.

Use the pinned Node version to avoid package installation and build failures from an older runtime. Use a separate test workspace to keep development files out of the application repository.

## Install the project

DocWriter pins Node 22.22.2 in `.nvmrc`. Clone the repository, switch to that version, and install the packages:

```sh
git clone https://github.com/docwriter-org/docwriter.git
cd docwriter
nvm use
npm install
```

If `nvm use` cannot find the version, run `nvm install` once.

## Start DocWriter

Run the application from the repository root:

```sh
npm run dev
```

Open `http://localhost:5173`. The same command starts the document server on port 3001.

By default, DocWriter treats the repository as the writing workspace. To test with another folder, run:

```sh
npm run dev:workspace -- --no-open /path/to/folder
```

## Check your change

Run both checks before you open a pull request:

```sh
npm run check
npm run build
```

`npm run check` checks TypeScript and Svelte files. `npm run build` checks the production build.

The project does not have a unit test suite. Provider smoke tests live in `e2e/` and need credentials for the provider you test.

The setup is ready when the editor opens at `http://localhost:5173` and loads a file from the chosen workspace. Both check commands should exit without errors.
